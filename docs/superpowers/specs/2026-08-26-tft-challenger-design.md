# tft-challenger 설계

작성 2026-08-26 · 상태: 승인 대기

## 1. 문제

한태영은 전 그랜드마스터, 지금 브론즈~골드에서 재등반 중. KR 서버.
metatft.com/comps를 쓰는데 불편한 이유 넷:

1. 지금 상황에서 뭘 해야 하는지가 안 나온다
2. 최종 보드만 보여주고 **거기까지 가는 과정**이 없다
3. 자기 티어 기준이 아니다
4. 갱신 주기를 자기가 못 정한다

리서치 결과 셋 중 셋은 이미 공짜로 해결돼 있다:

- (3) metatft에 아이언까지 내려가는 랭크 필터 + KR 서버 필터가 이미 있다. 기본값이
  Platinum+라서 안 보였을 뿐. `rank=BRONZE,SILVER,GOLD&server=KR`로 3일치 19만 판,
  7일치 54만 판이 나온다.
- (4) metatft 1시간 주기, op.gg 40분 주기. 갱신은 만들 게 아니라 갖다 쓰는 것.
- (1) TFTSense($25 평생)가 이미 판다. 상점 슬롯별 BUY/SKIP, 경합 감지, 포지셔닝.
  단 윈도우 전용 · 고티어 메타 전용 · 언리얼 전환으로 오버레이 업계가 깨지는 중.

**남는 구멍은 정확히 하나다:**

> 브실골(KR) 데이터로 계산된 단계별 빌드업 경로를, 한국어로.

metatft는 단계별 보드를 갖고 있으나 **다이아+ 것만** 있고, 브실골 데이터를 갖고 있으나
**최종 보드 통계만** 있다. 두 축을 아무도 안 합친다. TFT Academy는 경로가 있으나
티어 구분이 없다. 한국 도구는 둘 다 없다.

이 구멍이 실재한다는 근거: "ELO Trap" 분석 — 덱의 **68%가 티어가 오를수록 성적이
나빠지고, 32%는 순수 저티어 전용**이다. 한 덱은 티어별 단조 감소가 r=+0.998.
"고티어 라인이 골드 실행력으로는 안 굴러간다"는 의심이 데이터로 뒷받침된다.

## 2. 만드는 것

정적 치트시트 한 페이지. 게임 시작 전·판 사이에 폰이나 듀얼모니터로 본다.
실시간 조언 아님(Riot 정책 위반). 입력 UI 없음.

성격: **날카로운 소수정예.** 첫 화면은 "이번 패치 너의 3덱"이고, 나머지 색인은 접혀 있다.
저티어 등반의 정석은 덱을 많이 아는 게 아니라 소수를 반복해 파는 것이라서.

### 덱 카드

```
○○ 리롤                        브실골 KR · 3일 · 1,240판
────────────────────────────────────────────────────
평균등수   브실골 4.08  │  다이아+ 4.61   Δ -0.53 저티어전용
등수분포   ███▅▂▁▁▁
픽률 11%   → 8인 로비 기대 경합 0.8명 (나 말고 한 명은 거의 늘 있다. 정찰 필수)

단계 경로  [다이아+ 데이터]
  2-5 ▸ 3-2 ▸ 4-1 ▸ 최종
  ⚠ 브실골 보정: 9렙까지 밀어도 됨 — 초중반 피해가 덜하다 [출처]

캐리 / 아이템 / 카운터
```

**AVP만으로 정렬하지 않는다.** AVP는 "덱이 세다"와 "좋은 상황에서만 가는 덱이다"를
한 숫자로 뭉갠다. 등수 분포(8버킷)와 픽률을 같이 보여주고, 정렬 기본값은 Δ다.

### 색인 넷

덱 목록 · 아이템 · 증강 · 유닛. 같은 데이터에 색인만 다르게 둔 것이라 비용이 싸다.
게임 중 실제 진입점은 아이템("활 두 개 나왔다")이지 덱이 아니다.

### 패치 배너

패치가 감지되면 상단에:

- **덱 diff** — 직전 안정 데이터 대비 3덱의 AVP 변화, 새로 진입/이탈한 덱.
  data/daily/가 git에 쌓이므로 외부 의존 없이 계산된다.
- **공식 노트 요약** — Riot 한국어 패치노트에서 **내 3덱에 걸리는 항목만** 발췌.
  전체 요약은 이미 어디에나 있다. LLM 호출은 패치 감지 시에만(2주 1회).
- **불안정 배지** — 패치 후 3~5일은 데이터가 안 굳는다. 그 기간 내내 표시.
  안 그러면 흔들리는 숫자를 보고 멀쩡한 덱을 버린다.

### 신뢰도 등급

한 화면에 성격이 다른 정보가 섞이므로 출처를 시각적으로 구분한다.
안 그러면 통계와 카더라가 섞여서 도구 전체를 못 믿게 된다.

| 등급 | 내용 | 갱신 |
|---|---|---|
| 📊 데이터 | MetaTFT 집계 숫자 | 매일 |
| 📋 공식 | Riot 패치노트 발췌 | 패치마다 |
| 🌐 컨센서스 | 웹·X·레딧에서 긁은 고수 의견. **출처 링크 없으면 게시 안 함** | 아래 참조 |

컨센서스는 갱신 주기가 하나가 아니다. 섞으면 안 변하는 걸 매일 다시 긁고,
변한 걸 안 긁는다. 세 통으로 나눈다:

| 통 | 예 | 갱신 |
|---|---|---|
| 불변 원칙 | 레벨·롤 타이밍, 50골드, 아이템 슬램 판단 | 셋 바뀔 때 |
| 저티어 특화 | "브실골은 덜 맞으니 고점 봐도 된다" | 셋 바뀔 때 |
| 이번 패치 | 셋 메커닉, 버프/너프 | 패치마다 |

불변 원칙 통이 제일 값지고 제일 안 썩는다. 셋이 바뀌어도 대부분 그대로 간다.

## 3. 구조

```
GitHub Actions (매일 KST 새벽 / 패치 감지 시 3일간 6시간마다)
  ├ fetch     MetaTFT ×5 + ddragon ko_KR  →  data/raw/ (gitignore)
  ├ validate  셋·패치·cluster_id 게이트    →  불일치면 정지
  ├ patchdiff 직전 data/daily/ 와 비교
  ├ notes     패치 감지 시에만 LLM 호출
  ├ build     조인 + Δ + 한글화            →  data/daily/YYYY-MM-DD.json (커밋)
  └ render    dist/index.html (단일 파일)
       ▼
   GitHub Pages
```

파이썬 여섯 파일 + HTML 하나. 프레임워크·DB·번들러 없음. 사용자 한 명.

### 부품별 책임

| 부품 | 한다 | 안 한다 |
|---|---|---|
| `fetch` | HTTP 받아서 원본 그대로 저장 | 파싱·가공·판단 |
| `validate` | 셋/패치/cluster_id 일치 확인 | 데이터 수정 |
| `patchdiff` | 직전 스냅샷과 비교 | 네트워크 접근 |
| `notes` | 패치노트 요약 생성 | 통계 해석 |
| `build` | 조인·Δ·한글화·축약 | HTML 생성 |

**조인 방식 (중요).** `early-comps`의 stage-5 보드와 `comps_data`의 최종 덱은 id로 이어지지
않는다. 클러스터 공간이 다르고, `early-comps`의 `cluster`는 스테이지 내 인덱스일 뿐이다.
양쪽 모두 유닛 목록을 주므로(early=`units`, 최종=`units_string`) **유닛 집합의 Jaccard
유사도로 매칭**한다. 임계값 미달이면 그 덱은 단계 경로 없이 통계만 표시하고 매칭 실패를
로그에 남긴다. 억지로 붙이지 않는다 — 틀린 경로가 경로 없음보다 나쁘다.
| `render` | HTML 출력 | 계산 |

### 데이터 출처

**MetaTFT** (`api-hc.metatft.com`, `api.metatft.com`) — 비인증.

- `tft-comps-api/latest_cluster_id` — **먼저 뽑아서 `comps_*` 계열 전부에 물린다.**
  안 물리면 `comps_stats`와 `comps_data`가 서로 다른 덱을 말한다.
  ⚠ `early-comps`는 **다른 클러스터 공간**이다(실측: comps=409, early=2630). 여기엔 안 물린다.
- `tft-comps-api/comps_stats?queue=1100&patch=current&days=3&rank=BRONZE,SILVER,GOLD&server=KR`
- `tft-comps-api/comps_data` + `comp_options` — 덱 정의, 레벨 6/7/8/9 보드
- `api.metatft.com/tft-early-comps/comps_overview` — 스테이지 2/3/4/5 보드 +
  `forwards_links` 전환 가중치. **다이아+ 전용** — `rank`/`server` 파라미터를 붙여도
  응답이 동일하다(실측 확인). 단계 경로의 티어 분리는 불가능하다. 이것이 이 프로젝트의
  핵심 제약이며, 경로는 "다이아+ 것"으로 명시하고 보정 주석을 얹어 다룬다.
- `tft-comps-api/comp_details?comp=…` — 카운터

MetaTFT를 고른 이유: ToS 전문에서 scrape/crawl/bot/API/reverse-engineer 조항 **0건**,
robots.txt 전체 허용. 공개 repo에 올려도 문제가 없는 유일한 집계 소스다.

**Riot Data Dragon** — `ddragon.leagueoflegends.com/cdn/{ver}/data/ko_KR/tft-{champion,trait,item,augments}.json`.
한글 이름표. 셋18 이미 완비(특성 36, 증강 253).

**CommunityDragon** — 특성 발동 구간(`effects[].minUnits/maxUnits`)과 아이템 조합식(`from[]`).
ddragon에 없는 것만. ⚠ 셋 출시 직후 며칠은 CDragon이 한 패치 뒤처지고 셋18 유닛 목록이
스텁 상태다. 그동안 유닛은 ddragon에서, 구간·조합식은 나중에.

**제외한 것과 이유:**

| 소스 | 왜 안 쓰나 |
|---|---|
| Riot API | 매치 데이터에 단계별 보드가 없다(타임라인 엔드포인트 자체가 없음). 개발 키는 24시간마다 죽고, 개인 키는 승인 대기 3~8개월 |
| tactics.tools | 랭크 구간 최저가 Platinum+. 골드 플레이어에겐 무용이 아니라 오도 |
| dak.gg / lolchess | ToS 제11조(8)ㅅ 복제·제3자 제공 금지, 제15조(3) 임의 가공 금지. **public repo와 양립 불가** |
| Blitz | "개인·비상업" 라이선스, 복제·전송 금지. robots.txt가 봇 차단. **public repo와 양립 불가** |
| mobalytics | ToS가 크롤러·데이터마이닝 명시 금지 |

### Riot 서드파티 정책

정책은 "게임 전 정적 추천"을 **명시적으로 허용**하고 — 같은 추천이 게임 내내 화면에
떠 있어도 무방하다고 적혀 있다 — "현재 게임 상태 기반 제안", 게임 중 로비·상대 통계
표시(로딩 화면 포함), Legend 승률 표시를 **명시적으로 금지**한다.
이 프로젝트는 허용 쪽에 정확히 앉는다. 실시간 기능은 설계상 배제.

"데이터 없음 + 기본기 화면"으로 대체.

덱 하나당: `cluster`(스테이지 내 인덱스) · `name`(유닛 apiName 나열) · `units` ·

`stats` 안에 쓸 만한 필드:

- `final_place_avg` — **이 스테이지에 이 보드였던 사람의 최종 평균등수.**
  "이 초반 보드가 좋은 초반 보드인가"에 직접 답한다
- `matchup_avg_hp_delta`, `avg_hp` — 스테이지별 체력 손익.
  "브실골은 초중반에 덜 맞으니 고점을 봐도 된다"는 이 프로젝트의 전제를 재는 지표다.
  다이아+ 표본이라 절대값은 못 쓰지만 덱 간 상대 비교로는 쓴다
- `latest_stats` — 최신 패치분만. 패치 diff에 쓴다

### early-comps 경로 역추적 (실측)

- `units`는 리스트가 아니라 **딕셔너리** — 유닛 apiName이 키, 값은 `{"1-star": {...}, "2-star": {...}}`.
  유닛 집합은 `set(comp["units"].keys())`.
- `backwards_links[i]`의 길이가 이전 스테이지 덱 수와 정확히 일치한다
  (stage-3→38, stage-4→46, stage-5→49). stage-2에는 `backwards_links`가 없다(뿌리).
- 따라서 경로 복원은 stage-5 인덱스에서 `backwards_links` argmax를 세 번 타면 된다.
